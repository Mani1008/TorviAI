VS Code / Cursor — Strategy 0 Detail

🔌 Why VS Code needs a dedicated strategy ▶

VS Code's accessibility tree exposes the entire IDE: Explorer sidebar, Source Control panel, Outline, Timeline, NPM Scripts, Breakpoints, status bar, terminal — everything. Strategy 0 detects VS Code / Cursor via window title and searches directly for the editor pane.

Find workbench.parts.editor
Search tree for AutomationId match → find all Document children → IUIAutomationTextPattern on each → keep longest result.
Fallback: ClassName monaco-editor
If step 1 returns empty, try ClassName match for monaco-editor → TextPattern.
Scoped tree walk
If both fail (Welcome tab, Settings UI, extension views) → walk_children() scoped to the VS Code window root. Never falls to Strategy 1 which would read the full sidebar tree.

Browser Strategy 1.5a — RootWebArea Hard-Scoping

🌐 Chrome / Edge / Brave scoping detail ▶

The RootWebArea element is hard-scoped: if TextPattern on the web element returns empty (Google Docs canvas scenario), it falls back to a filtered tree walk scoped to the web element — not the root window.

⚠ A hard return Ok(String::new()) after both attempts prevents any escape to the root-window walk that would read browser chrome again (address bar, bookmarks, tab list).

Tree Walk Filter — walk_children()

✓ Collected types

Text, Edit, Document, Hyperlink, TreeItem, DataItem, Header, ListItem, Group

✕ Skipped types

Button, ToolBar, MenuItem, MenuBar, ScrollBar, StatusBar, TitleBar, Separator, AppBar, TabControl, TabItem, CheckBox

Depth cap: 15 levels. Raw capture limit: 20,000 chars at all strategies.

RS ⏱ Context Watcher

src-tauri/src/app_context.rs — long-running background loop. Two triggers. One capture/emit/save pipeline.

Dual Triggers

A WinEvent Hook

SetWinEventHook EVENT_SYSTEM_FOREGROUND

Fires instantly (<1ms) on foreground window switch. Lives on a dedicated OS thread with a Win32 message pump. Sends signal via mpsc::channel(4).

300ms debounce — waits for new window to finish painting before UIAutomation reads.

Always re-captures even if content hash matches — window switch forces re-emit to keep UI timestamp fresh.

B 2-Second Timer

tokio::time::interval(2s)

Catches content changes inside the same window — user typing, page loading, dynamic content updates.

On timer trigger with unchanged hash: skips re-capture unless last emit was >360s ago (STALE_SECS) — forces re-emit so AI context does not go dark during long reading sessions.

RS 🗄 Context DB

src-tauri/src/context_db.rs — direct sqlx SQLite writer. Bypasses tauri-plugin-sql IPC entirely (the JS IPC path silently dropped writes with rowsAffected=0).

🚩 Why bypass tauri-plugin-sql? The JS IPC path silently dropped INSERT statements — rowsAffected = 0, no error, no log. Direct sqlx writes from Rust work reliably. WAL journal mode allows both pools to coexist on the same file without blocking reads.
📋 Rust Pool (sqlx)

All writes — INSERT chunks, schema migrations. max_connections=1. WAL mode.

📄 JS Pool (tauri-plugin-sql)

All reads — getRecentContext(), UI queries. Read-only access to the same ai_assistant.db.

Schema — context_chunks table

src-tauri/src/context_db.rs
SQL 
CREATE TABLE IF NOT EXISTS context_chunks (
  id                TEXT    PRIMARY KEY,        -- UUID v4
  app_name          TEXT    NOT NULL,
  window_title      TEXT    NOT NULL,
  content_type      TEXT    NOT NULL,
  text_content      TEXT    NOT NULL,             -- one sliding-window chunk
  content_hash      TEXT    NOT NULL,             -- SHA-256 of full cleaned text
  captured_at       INTEGER NOT NULL,             -- Unix timestamp seconds
  url               TEXT,
  parent_capture_id TEXT,
  chunk_index       INTEGER NOT NULL DEFAULT 0
);

-- 5 indexes for fast queries
CREATE INDEX idx_ctx_captured_at  ON context_chunks(captured_at DESC);
CREATE INDEX idx_ctx_hash         ON context_chunks(content_hash);
CREATE INDEX idx_ctx_app          ON context_chunks(app_name);
CREATE INDEX idx_ctx_app_time     ON context_chunks(app_name, captured_at DESC);
CREATE INDEX idx_ctx_parent       ON context_chunks(parent_capture_id);

Chunking Strategy

📈 Window Size

10,000 chars per chunk
≈ 2,500 tokens — holds a complete function with surrounding context

🔁 Overlap

1,000 chars (10%)
Prevents BM25 from missing a hit spanning a chunk boundary

🗑 Min Chunk

20 chars minimum
Chunks shorter than 20 chars are dropped silently

🔗 ID Linkage

Chunk 0: parent_capture_id = NULL
Chunks 1..N: parent = first chunk ID + positional hash suffix "hash:N"

❚ Dedup Window

SHA-256 hash checked against last 5-minute window. Matching hash within 5min → skip INSERT entirely.

10-Step Retrieval Pipeline

Over-fetch
getRecentContext(20, 30) — 20 candidate chunks from the last 30 minutes.
Tokenise corpus
[a-z0-9_]{3,} tokens; buildCorpus() computes IDF statistics across all candidates.
Tokenise query
Current message + last 3 user turns → deduplicated token set.
BM25 score
Robertson–Spärck Jones IDF formula per chunk. Parameters: k1=1.5, b=0.75.
Recency bonus
Add +3.0 to chunks captured < 5 min ago (RECENCY_FRESH_SECS=300).
Filter
Drop chunks with score < BM25_MIN_SCORE (0.5).
Sort
Descending by final score.
Per-app dedup
First (highest-scoring) occurrence per app_name; up to 3 chunks per app (RAG_MAX_CHUNKS_PER_APP).
Hard cap
slice(0, 10) — never inject more than RAG_MAX_CHUNKS chunks.
Truncate & inject
Each chunk truncated to 2,000 chars at a line boundary. Injected as a ## Current Screen Context block in the system prompt.

TS 💻 UI & Events

src/pages/context-memory/index.tsx + src/pages/app/index.tsx — the live UI layer built on top of the Rust pipeline.

Event Timeline — Backend → Frontend

context-captured
Emitted by app_context.rs after cleaning & dedup. Payload: AppContextSnapshot with app_name, window_title, text_content, content_type, content_hash, url, captured_at
UI reaction: increments session counter · lights the live "Watching" dot · triggers proactive suggestion chips in overlay
context-chunks-saved
Emitted by context_db.rs after all SQLite INSERTs commit.
UI reaction: triggers loadChunks() to reload the DB view — ensures UI shows committed data, not just event data
google-docs-needs-screen-reader
Emitted when Google Docs URL detected but text < 150 chars (canvas-rendered document body invisible without screen reader mode).
UI reaction: shows a dismissable yellow banner prompting Ctrl+Alt+Z in Google Docs

Context Memory Page Features

🏠 Filter Tabs
All / Code / Docs / Email / Chat / Meeting / PM / Generic — filters context_chunks by content_type

Calls stop_context_watcher / start_context_watcher Tauri commands. Intent stored in localStorage["ctx_watcher_paused"] — shared across all webviews.

Design Constraints

🏴 Windows-only. UIAutomation is a Windows API. macOS/Linux return an error gracefully.
🔗 WAL mode. Rust sqlx pool can write concurrently with the JS-side read pool without blocking.
⏱ 24h rolling window enforced on retrieval, not on storage. Keeps knowledge base fresh.
